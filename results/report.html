执行摘要

本项目从零 Python 基础起步，使用 Microsoft Qlib 框架对 A 股市场进行系统化量化策略研究， 历经 9 轮迭代 + 1.5 轮方法论校验，在严格防过拟合的前提下，最终确立了一个 真实可信、无方法论隐患的多头选股策略：

★ 最终最优配置
CSI500 历史并集 + Alpha158 + LightGBM 默认超参 + TopkDropoutStrategy(topk=30, n_drop=1)
5.4 年含真实历史成分变更回测、含双边 0.3% 交易成本

项目核心价值

项目的真正成就不在于"高 IR"（0.45 仍低于实战可用线 1.0）， 而在于建立了严谨、可复现、零方法论隐患的研究流程。

所有"漂亮数字"都经过去偏 / 长测试集 / 不碰测试集的反复校验：

  • 第 1 轮的 +8.85%（短测试集海市蜃楼）→ 第 2 轮长测试集打回 −0.97%
  • 第 7 轮的 +14.94%（幸存者偏差版本）→ 第 8 轮去偏后打回 +3.91%
  • 第 9 轮试图通过集成 / 行业中性化突破 +4.40% → 全部失败，反而印证当前框架已到上限

剩下的 +4.40% / IR 0.45 是经过所有方法论审查后的真金白银。

熊市防御性突出
2022 年中证500 指数跌 −20.4%，本策略仅跌 −5.6%（净超额 +14.8%）， 显示出明确的"抗跌"特性。

方法论收获概览

  1. 长测试集是底线，不是可选 — 5 个月测试集救了我们一次潜在实盘灾难
  2. 降换手是免费午餐 — 第 3 轮模型不变、净超额 −0.97% → +2.81%
  3. IC 涨 ≠ 回测涨 — 项目 5 次出现该现象（R4、R5、R8.5 重调、R9 集成、R9 中性化）
  4. 战场决定上限 — CSI500 vs CSI300 同模型 IR 翻倍多
  5. 简单胜过复杂 — 最终配置打败 200+ 轮 Optuna 调出的复杂方案
  6. 幸存者偏差实际虚高 11 pp（远超经典估计 2-4 pp），中盘股尤甚

1   项目背景与方法论

1.1 研究目标

项目同时承担学习与实证双重目标：

  • 学：边做边学量化研究的完整方法论流水线 — 数据采集 → 因子工程 → 模型训练 → 策略构建 → 回测评估 → 迭代改进
  • 做：在 A 股市场，在严格防过拟合的前提下，找出净超额 > 0 且经得起任何审查的可信策略
  • 守住的底线：所有结论必须能通过方法论复审；不接受任何"看上去很美"的回测

1.2 防过拟合铁律（贯穿全项目）

从 CLAUDE.md 中定义、9 轮研究中严格执行的 5 条铁律：

#规则用例与说明
1长测试集测试期至少 3 年、最好 5+ 年，需跨越牛熊市
2严格不碰测试集超参搜索 / 策略调参只能在 2018-2019 验证集上做；测试集 2020-10 ~ 2026-05 只在最终评估时跑一次
3必含交易成本A 股双边 0.3%（佣金 + 印花税 + 滑点）写死在每个回测里
4历史成分股股票池要用真实历史成分（每年都不同），不能只取"今天还在指数里的赢家"
5警惕完美回测年化 >50%、IR >3 一定是有问题；要倒查

这 5 条规则在项目中被反复印证——每一条都救过我们一次。比如第 1 轮 9 个月测试集给出 +8.85% IR 1.04， 第 2 轮一旦延长到 5.4 年立刻打回 −0.97%。如果没守住"长测试集"这条规则，我们会以为找到了"圣杯"。

2.2 采集过程踩坑

baostock 限流是核心挑战。经历了如下迭代：

#策略结果
18 worker 并发387/790 失败（IP 级限流）
2降到 4 worker + 失败重登勉强 ok，仍有部分失败
3单线程兜底 + 1s 间隔0 失败但很慢
4加 socket.setdefaulttimeout(30)避免 baostock 半挂死无限阻塞
5多分片 + 循环重试 + 轮间冷却最终方案：791+784+120 = 1695 只无失败

2.3 关键工程脚本

  • baostock_collector.py — OHLCV 多进程采集（含历史成分股查询）
  • valuation_collector.py + fetch_val_loop.py — 估值采集 + 循环兜底
  • build_qlib_data.py — CSV → qlib 二进制格式
  • collect_industries.py — 行业归属（第 9 轮中性化用）

ROUND 1  ·  CSI300 BASELINE
经典基线 LightGBM + Alpha158（9 个月）
假设 → 用 158 个量价因子的工业基线在 A 股能跑出可观超额

实现：qlib 自带 Alpha158 + LightGBM + TopkDropoutStrategy(topk=50, n_drop=5)，CSI300 上跑 2020-01 ~ 2020-09。

结果：净年化超额 +8.85%，信息比率 1.04。

⚠ 埋雷时刻
测试集只有 9 个月，且恰逢 2020 上半年牛市。数字可信度低。"好看的数字不一定是真的"——这是项目的第一个教训。
ROUND 2  ·  LONG TEST SET
5.4 年长测试集 — 现实一巴掌
假设 → R1 可能是短期幸运，需要长测试集检验

实现：自建 baostock 数据管线，拉 790 只 CSI300 历史并集（消除幸存者偏差），测试期扩到 5.4 年。 配置完全不变。

结果：净超额 −0.97%，IR −0.12。

★ 收获
R1 的 +8.85% 是 2020 牛市的海市蜃楼。延长测试期立即打回原形。多 5 个月的努力就避免了一次潜在的实盘灾难。
ROUND 3  ·  LOWER TURNOVER
降换手 — 救活了策略
假设 → 毛超额 +6.74% 是活的，但年化成本 7.7% 把它全吃了

实现：只改一个参数 n_drop 从 5 → 1。其他全不变。

6   核心方法论收获

这 6 条收获是 9 轮研究的"投资价值最大"的部分。每一条都来自真实的"踩坑后顿悟"， 比"得到正确数字"更值钱。

1. 长测试集是底线，不是可选
R1 9 个月给 +8.85% / IR 1.04；R2 同配置 5.4 年立刻打回 −0.97% / IR −0.12。 多 5 个月的努力就避免了一次潜在的实盘灾难。任何短测试集（<3 年）的回测都要打狠折扣。
2. 降换手是免费午餐
R3 把 n_drop 5 → 1，模型/因子/超参全不变，净超额 −0.97% → +2.81%。 70% 的提升来自策略层一行参数。交易成本是量化里的"暗杀手"——A 股双边 0.3% 看似不大， 高换手下年化能吃掉 7-8% 的纸面 alpha。
3. IC 涨 ≠ 回测涨（项目 5 次出现）
R4 加估值（IC +16% / 回测 −0.3pp）、R5 调超参（IC +6% / 回测 −0.7pp）、R8.5 v4 重调（验证 RankICIR +8% / 测试 IR −0.05）、 R9 集成（IC 持平 / 回测崩盘）、R9 行业中性化（ICIR +17% / 回测崩盘）。同一反直觉现象 5 次重演。

背后本质：IC 衡量"全部 500 只股票排序对不对"，但 TopK=30 只关心最尖端 30 只。 整体排序变好不等于尖子选得更好。优化目标和真实目标永远有缝。
4. 战场决定上限
CSI300 上 5 轮努力 → 上限 IR 0.37。CSI500 同样的工具 → IR 0.45（去偏后真实数字）。 最大边际产出来自换战场，不是打磨模型。CSI300 太被机构套利充分了。
5. 简单胜过复杂
最终最优配置 = qlib 默认超参 + topk=30 一个改动，打败了 200 轮 Optuna 搜索调出的复杂超参组合。 每一轮"看起来更复杂的方案"都没能赢过"简单方案"。过度拟合是过度优化的另一个名字。
6. 幸存者偏差实际虚高 11 pp（远超经典估计）
经典文献估算小盘股幸存者偏差年化虚高 2-4 pp。我们的实测是 11 pp！

R7 含偏版 +14.94% → R8 去偏版 +3.91%。在中盘股（中证500）淘汰率高的环境下，偏差严重得多。 任何"只用当前成分"的回测都要打狠折扣。

7   未来路线图

项目走到 R8.5 + R9，已确认在 Alpha158 量价因子框架下到达天花板。要再上一台阶，必须换信号源。 按工作量 / 预期收益排序：

🟢 短期（1-2 天工作量，纯本地数据）

  • 组合优化器：替代 TopK 为带约束（行业上限、波动率上限、个股权重）的组合优化
  • 分层 long-only：分 5/10 层多空表现，识别哪些股票区间最有 alpha
  • 风险因子调控：在 Barra 风格上做暴露归因，去掉非主动风险

🟡 中期（1-2 周工作量，需新数据源）

  • 加财务因子（季度 ROE / 营收增速 / 毛利率等）—— 需点位安全处理（财报披露日延迟）
  • 加一致预期因子（分析师评级 / 调研频次）—— 需 Wind / 同花顺等付费源
  • 扩到 CSI1000 或全市场 —— baostock 无 CSI1000，需 akshare 接
  • 深度学习模型（LSTM / Transformer / TCN）—— 装 PyTorch 已就绪

🔴 长期（大投入，需团队/资源）

  • 高频微观结构因子（tick 级订单流），需付费数据，工作量数月
  • 另类数据（卫星图像、新闻 NLP、信用卡支出、招聘数据）
  • 实盘小规模验证（10 万 → 50 万 → 200 万 → 全仓递进）—— 需券商接口接通
给项目本身的建议
  • 当前 IR 0.45 不足以独立实盘——实战通常需要 IR ≥ 1.0，且需要多策略组合分散风险
  • 这个项目作为"研究方法论训练"已成功；作为"实盘策略"还差至少 IR 0.5 的距离
  • 真要实盘，推荐路径：集成模型 → 加财务因子 → 多策略组合 → 小规模实盘

  2. numpy 2.x 与 qlib 不兼容 → 锁 numpy<2
  3. conda 新版需接受 ToS → conda tos accept --override-channels --channel ...

  6. baostock 8 worker 并发被限流（387 失败）→ 降到 4 worker + 自动重登
  7. 4 worker 仍部分被限 → 单线程兜底 + 1 秒间隔
  8. baostock 连接半挂死，retry 接不住 → 设 socket.setdefaulttimeout(30)
  9. 多 shard 并行被 IP 级限流 → 单连接慢节奏 + 多轮循环

  11. Python heredoc + lightgbm 多进程冲突 → 写成正式 .py 脚本
  12. n_drop=0 在 qlib 中实际是每日全换 → 这选项是个坑
